# ADR 003 — SQLite virtual tables before DataFusion

Status: accepted for this prototype; DataFusion remains an analytical-engine candidate.

[DataFusion's TableProvider](https://datafusion.apache.org/library-user-guide/custom-table-providers.html)
supports a schema, execution plans, and pushdown hints for projection, filters and
limits. It is a suitable future route to Arrow batches and parallel analytical
execution. It is not necessary to validate the initial relational kernel.

Use [SQLite virtual tables](https://sqlite.org/vtab.html) through rusqlite.
Each registered table holds an authorized immutable Liquid snapshot. The planner's
best-index callback offers identity lookup and one equality role index; its cursor
calls the native authorized lookup/scan path. It does not copy all relations into
ordinary SQLite tables before applying filters. Snapshot handles reject writes, ATTACH, PRAGMA changes and extension loading.
The subsequent DX milestone adds a separate explicit SqlTransaction with writable
callbacks routed through the native kernel; failures abort the whole transaction.
Only one result-producing, read-only statement is accepted per query call.

Do not omit SQLite's final predicate recheck. Push only BINARY-collation equality
with a lossless native value conversion; otherwise scan and let SQLite apply its
coercion rules. This is intentionally conservative. Views are local to one SQL
snapshot, use invoker permissions, and are read-only. Prepared queries reuse that
snapshot and statement while parameters change.

Consequences: usable joins, aggregates, SQL bags and outer-join NULLs now, with a small
synchronous adapter and a baseline independent from Liquid's native query execution.
The cursor materializes candidate rows, not an Arrow stream. Range, limit and projection
pushdown, PostgreSQL protocol compatibility, persisted views,
and exact decimal arithmetic are not claimed. Decimals expose minor-unit INTEGERs.
The attached-schema namespace count is limited by the bundled SQLite configuration.

The first sketch proposed materializing snapshots into SQLite tables. The added
specification made avoiding whole-store materialization explicit; that sketch was
replaced before implementation by the virtual-table provider. Prepared-query support
was added to measure execution separately from repeated parsing.


DX update: snapshot cursors page 64 rows instead of buffering entire candidate
families. Transactional cursors retain stable statement candidates. Remote SQL has
row/byte/VM and SQLite value-size limits, while native policy work is not fully
budgeted. SQL INSERT requires an explicit UUID; identity mutation and RETURNING
are unsupported. Read-only snapshot behavior and query interoperability remain.
